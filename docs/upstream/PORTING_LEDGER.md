**License rule (applies to every row below):** no license was found
in the upstream repository (no `LICENSE` file, no grant in README /
AGENTS / CHANGELOG, GitHub license API `null`, checked 2026-11-20).
`verbatim_allowed` is therefore `false` for every upstream module
until an explicit license or written permission is recorded. Porting
means behavioral specification + Muse-original reimplementation, with
tests. A row may only change to verbatim-allowed when the grant is
recorded here with its source.

**v0.3.1 license update (R5, 2026-11-24):** upstream tag v0.3.1
(`418797a4`, 2026-11-21) adds a standard `Apache-2.0` root `LICENSE`
(`Copyright 2026 SkyOneBranch`; GitHub contents-API blob SHA

verified markers: `Version 2.0, January 2004`, `END OF TERMS AND
CONDITIONS`, `APPENDIX`). The repo-level license API still returns
`NOASSERTION` — the default branch carries no `LICENSE`; the grant
exists at the v0.3.1 tag only. R5 performed no verbatim import, so
`verbatim_allowed` stays `false` for every row below; flipping it
for v0.3.1-tagged files (which would require attribution + license
retention per Apache-2.0 §4) is a separate decision for the
integration lead, not part of this ledger refresh. The Muse repo
itself has no `LICENSE` file; adopting one for Muse is likewise a
separate decision.

**Never merged, never mirrored:** the upstream repo is fetched
read-only into a separate directory; no `git merge` of an upstream
branch, no `.git` copy, no mirror push, no overwrite of the Muse
worktree.
